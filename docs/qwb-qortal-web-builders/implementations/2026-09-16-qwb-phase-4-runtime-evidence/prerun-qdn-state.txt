## Caveat on the per-name sections above
The `names=<...>&exactMatchNames=true` query parameters were NOT honoured by this node for
`/arbitrary/resources/search` (each name returned the same 50 foreign `qwb_ix_*` rows). The earlier
Phase 3 finding stands: server-side name filtering cannot be relied on and the app's client-side
re-filter on the exact `(name, service, identifier)` is load-bearing. The single-`name` form used in
`live-qwb-website-search.json` does filter correctly.

The unambiguous pre-run signal is therefore the site-singleton FETCH above (HTTP error 1401,
"Couldn't find PUT transaction") plus the DOCUMENT searches: **no QWB app resource exists under any
candidate publishing name**, so the first add would be unambiguous.
